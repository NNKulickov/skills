# System Block Model - стиль для архитектуры, систем и пайплайнов

Обязательный режим, когда просят **архитектуру, блок-схему, устройство системы или
пайплайн**. Он перебивает «Comprehensive/Technical» из SKILL.md: плотная
информационная карта с колонками, врезками кода и абзацами подписей для этой задачи
**неверна**, сколько бы фактуры в ней ни было.

## Когда включается

Список триггерных слов - в SKILL.md, секция «System Block Model»; здесь только границы.

Режим включается и тогда, когда триггерное слово не прозвучало, но объект - работающая
система с фазами, компонентами и потоком между ними.

**Не включается** для: таймлайнов, сравнений двух вариантов, деревьев решений,
объяснения одного алгоритма, ментальных моделей без компонентов.

---

## Один абзац сути

Крупные блоки в один-два слова, вложенные именованные контейнеры, много воздуха,
поток слева направо: вход → фазы → результат. Сквозное правило системы - пунктирная
рамка **поверх** фаз, а не ещё один блок в ряду. Всё, что не влезает в блок, уходит
в подпись под моделью, а не внутрь неё.

## Бюджет (жёсткие потолки)

| Параметр | Потолок | Почему |
|---|---|---|
| Элементов всего | **~110** | 139 уже нечитаемо; 97-108 - рабочий диапазон |
| Блоков внутри одного контейнера | **5** | шестой означает, что контейнер надо делить |
| Строк текста в блоке | **2** | название + уточнение в скобках |
| Символов в строке блока | **~40** | иначе шрифт придётся ронять ниже 15px |
| Свободных подписей рядом с блоками | **0** | подпись к каждому блоку = ковёр |
| Evidence-врезок (тёмный код/JSON) | **0-1** | в блок-модели почти всегда 0 |
| Уровней вложенности контейнеров | **2** | сквозной слой → фаза → блок |

Не влезло в бюджет - режь содержание, а не размер шрифта и не воздух. Шрифт ниже
12px и зазор меньше 40px между блоками - признак, что бюджет уже нарушен.

## Канон компоновки

Слева направо, ровно в этом порядке:

```
[заголовок 34px + подзаголовок 16px в 2 строки]

        [лента фаз: 5-7 чипов 280x64 со стрелками между]

┌─ вход ─┐   ┌═══ СКВОЗНОЕ ПРАВИЛО (пунктир) ═══════════════════════┐   ┌ результат ┐
│ 340x300│ → │ ┌ фаза 1 ┐ ┌ фаза 2 ┐ ┌ фаза 3 ┐ ┌ фаза 4 ┐          │ → │  320x140  │
│        │   │ │ блок   │ │ блок   │ │ блок   │ │ блок   │          │   └───────────┘
│        │   │ │ блок   │ │ ┌цикл┐ │ │ блок   │ │ блок   │          │
└────────┘   │ │ блок   │ │ └────┘ │ │ блок   │ │        │          │
             │ └────────┘ └────────┘ └────────┘ └────────┘          │
             │ • правило  • правило  • правило                       │
             └══════════════════════════════════════════════════════┘

        [полоса общего ресурса: хранилище / шина / реестр]
        [полоса «где остаются люди» или другой второй срез]

[легенда 14px: как читать цвет + один замер цифрами]
```

Обязательные элементы канона:

1. **Лента фаз сверху** - Level 1 summary: 5-7 чипов `280x64`, текст 13px, стрелка
   30px между соседями. Читается за две секунды и задаёт словарь всей схемы.
2. **Вход слева** - большой блок `340x300` с заливкой и свободным текстом внутри:
   заголовок 17px + тело 13px через пустые строки. Не таблица, не список с буллетами.
3. **Сквозное правило пунктиром** - то, что действует поверх всех фаз (безопасность,
   круг возврата, SLA, аудит). Заливка светлая (`#fee2e2` для правила-ограничения),
   рамка 2px dashed, подпись 18px в левом верхнем углу, под ней одна строка 13px.
   Внизу рамки - 2-3 буллета с точкой-эллипсом 12px.
4. **Контейнеры фаз** - прозрачная заливка, цветная рамка 2px solid, подпись 16px в
   углу `(x+24, y+16)` вида `1 · Квалификация · шаги 01-10`. Высота **по содержимому**,
   а не одна на всех: пустой низ у контейнера читается как «тут чего-то не хватает».
5. **Вложенный цикл** - если внутри фазы есть петля, она отдельный контейнер с
   подписью-строчной («круг правок без людей») и стрелкой возврата слева.
6. **Результат справа** - один блок с заливкой цвета успеха.
7. **Полосы под моделью** - сквозной ресурс (хранилище артефактов, шина событий) и
   второй срез (гейты людей). Ширина по ширине сквозной рамки.
8. **Легенда внизу** - 2-3 строки 14px: что означает каждый цвет и один замер
   цифрами, если он есть.

## Размеры и типографика

| Роль | Размер блока | Шрифт | Цвет текста |
|---|---|---|---|
| Заголовок схемы | - | 34 | title |
| Подзаголовок, 1-2 строки | - | 16 | body |
| Чип фазы в ленте | 280x64 | 13 | on light / on dark |
| Подпись контейнера | - | 16 | цвет рамки контейнера |
| Подпись сквозного слоя | - | 18 | цвет рамки |
| Главный блок фазы | 460-520 x 100-110 | 15-16 | on light / on dark |
| Блок внутри вложенного цикла | 150x90 | 12 | on light |
| Вход / результат | 340x300 / 320x140 | 13 / 16 | on light |
| Полоса ресурса | ширина слоя x 100 | 14 | цвет рамки |
| Легенда, сноски | - | 13-14 | body |

`fontFamily: 3` везде. `roughness: 0`, `strokeWidth: 2`, `roundness: {"type": 3}`.

Зазоры: между блоками в колонке **50-60px**, между контейнерами фаз **40px**,
от рамки контейнера до блока внутри **50px** сверху и **20-30px** по бокам.

## Цвет кодирует ответственность, а не красоту

В системах цвет отвечает на вопрос «кто это делает», и ответ должен быть один и тот
же на всей схеме:

| Кто | Заливка | Рамка |
|---|---|---|
| Решает модель / LLM / агент | `#ddd6fe` | `#6d28d9` |
| Детерминированный код, проверка | `#93c5fd` / `#60a5fa` | `#1e3a5f` |
| Человек, гейт, ручной шаг | `#fef3c7` | `#b45309` |
| Вход, внешний источник | `#fed7aa` | `#c2410c` |
| Результат, успех | `#a7f3d0` | `#047857` |
| Сквозное правило-ограничение | `#fee2e2` | `#dc2626` (dashed) |
| Контейнер фазы | `transparent` | цвет по смыслу фазы |

Тёмная заливка (`#60a5fa`, `#3b82f6`) требует белого текста - проверять на рендере,
а не на глаз в JSON.

## Антипаттерны - то, за что схему вернут

- **Колонки-дорожки вместо блоков.** Пять вертикальных зон, в каждой по семь коробок
  с подписями - это не архитектура, это таблица, нарисованная прямоугольниками.
- **Подпись у каждого блока.** Свободный текст справа от каждой коробки утраивает
  плотность и убивает чтение с расстояния.
- **JSON-врезки в блок-модели.** Тёмный прямоугольник с примером payload уместен в
  обучающей диаграмме протокола, но в схеме системы он забирает площадь у структуры.
- **Мелкий шрифт ради помещаемости.** 11-12px в главном блоке - сигнал резать текст.
- **Одна высота у всех контейнеров.** Пустые низы выглядят как незаконченная работа.
- **Сквозное правило как ещё один блок в ряду.** Оно рамка поверх, иначе теряется
  сам смысл слова «сквозное».
- **Тридцать стрелок.** Если стрелок больше, чем блоков, структура неверна.

## Чек-лист перед показом

Отвечать по отрендеренному PNG, не по JSON:

1. Схема читается с расстояния вытянутой руки, без зума?
2. Элементов не больше ~110, блоков в контейнере не больше пяти?
3. У каждого контейнера высота по содержимому, пустых низов нет?
4. Сквозное правило - рамка поверх фаз, а не блок в ряду?
5. Цвет означает ответственность и означает её одинаково везде?
6. Ни одной свободной подписи-абзаца внутри модели?
7. Поток читается слева направо: вход → фазы → результат?
8. Легенда внизу объясняет цвет и даёт хотя бы один замер цифрами?
