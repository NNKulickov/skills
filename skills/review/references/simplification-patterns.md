## Прогон `modernize`

Только Go-репозитории. Ревью-подсессия ищет баги; класс «это можно записать проще» она находит
нестабильно, а инструмент находит его детерминированно и с готовой заменой. Прогон read-only,
~1 с на дерево пакета:

```bash
modernize ./<пакет диффа>/... 2>&1 | grep -v '\.gen\.go:'
```

Ставится один раз: `go install golang.org/x/tools/go/analysis/passes/modernize/cmd/modernize@latest`.
Отдельный бинарь нужен потому, что в `golangci-lint` этот линтер появился только с v2.6.0, а
локально стоит более старая версия (проверено 2026-08; если `golangci-lint --version` уже отдаёт
v2.6+, проверку можно включить в его конфиге и бинарь не нужен). Документация и полный список
анализаторов - <https://pkg.go.dev/golang.org/x/tools/go/analysis/passes/modernize>.

Ловушки:

- находки идут в **stderr**, не в stdout - без `2>&1` файл будет пустым;
- `*.gen.go` дают лавину `omitzero`, а файлы с `DO NOT EDIT` править нельзя;
- `-fix` в ревью не запускаем вообще - мы код не меняем;
- набор проверок режется директивой `go` в `go.mod`: на `go 1.24` анализаторы уровня 1.26 молчат сами.

## Фильтр по строкам диффа

Прогон по модулю выдаёт сотни находок на чужом коде (на крупном монорепо - около полутысячи), поэтому фильтр
обязателен и он механический, а не на глаз:

```bash
git diff --name-only <BASE_REF>...HEAD        # какие файлы вообще трогает дифф
git diff -U0 <BASE_REF>...HEAD                # заголовки @@ дают диапазоны новых строк
```

Находка идёт дальше, только если её файл есть в первом списке **и** её строка попадает в диапазон
`@@ -… +N,M @@` из второго. Остальное - чужой код, и CI его тоже не увидит (`new-from-rev`).

## Паттерны, которые инструмент не находит

`modernize` видит только локальные шаблоны выражений. Отдельно пройди дифф по списку:

- **дубль механизма, который в репозитории уже есть** - свой ретрай/бэкофф/кэш/конвертер рядом с
  общим. Это про *внутрь модуля*: «а соседний модуль делает иначе» - отдельная проверка, см.
  «Сравнивай изменение с соседними модулями» в `review-engine.md` §3;
- **промежуточная сущность без пользователя**: слайс/мапа, собранная ради одного прохода; поле,
  всегда равное другому; параметр, у которого во всех вызовах одна константа; интерфейс с одной
  реализацией и одним вызывающим;
- **лестница вложенности вместо раннего выхода**;
- **две ветки, отличающиеся одной константой** - таблица вместо `switch`;
- **код, ставший мёртвым от самой этой правки** - удаляется в этом же диффе;
- **горутина/мьютекс/канал там, где хватает последовательного вызова**.

Формулируй как обычную находку - `file:line` + конкретная замена, а не «можно было бы аккуратнее»:

```
- [ ] pkg/xyz/mapping.go:88 - Minor - этот цикл собирает `ids` только чтобы один раз
      пройти его ниже; слить в один проход и убрать слайс
```

Скоуп тот же, что у всего ревью: **только внутри того, что дифф трогает.** Рефакторинг соседнего
кода «раз уж мы здесь» - не находка, а расширение MR.

## Severity

- находка `modernize` на новой строке диффа - проверяемая машиной, с готовой заменой → **Minor**;
- упрощение, найденное глазами по списку выше → **Suggestions**; исключение - дубль уже
  существующего в репозитории механизма и мёртвый код, созданный самой правкой: эти два случая
  **Minor**;
- ни одно упрощение само по себе не переводит вердикт в `CHANGES_REQUESTED`.
