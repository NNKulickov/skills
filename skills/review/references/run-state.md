# run-state - персистентный чекпоинт ревью

Механизм run-директории: сохраняет прогресс ревью между шагами так, чтобы его
можно было возобновить из другой сессии (даже спустя дни).

## 1. Расположение

```
$REVIEW_RUNS_DIR/<host>-<repo>-<mr>-<ts>/
```

База - переменная окружения `REVIEW_RUNS_DIR`, по умолчанию `~/.claude/review-runs`. Можно указать
любой рабочий каталог, который пользователь держит на виду. Главное - **не** `/tmp`: директория
должна пережить перезапуск сессии. Директория вынесена ИЗ каталога скилла
(`~/.claude/skills/review/`), чтобы переустановка/обновление скилла не сносила незавершённые
прогоны. Пример:

```
~/.claude/review-runs/gitlab.example.com-group-project-5375-20260724T192300/
```

Не собирай имя вручную: создание директории, санитизацию `host`/`repo` (слэши и
прочие небезопасные символы → дефисы), timestamp `<ts>` (`YYYYMMDDThhmmss`) и засев
`state.json` делает `scripts/run_dir.sh create <host> <repo> <mr>` - он печатает путь
к готовой директории. Механика именования живёт в скрипте, здесь её не дублируем.

## 1a. Дисциплина прав: scratchpad → stage (ВАЖНО)

Run-директория лежит **вне рабочего репо** (ревью идёт в worktree целевого репо, а прогоны -
в `$REVIEW_RUNS_DIR`), поэтому прямой `Write`/redirect в неё дёргает запрос прав на
каждый файл. Чтобы не отвлекать пользователя:

- Все **промежуточные** файлы шага (черновики `context.md`, `draft-review.md`, диффы и
  т.п.) пиши в **scratchpad сессии** (он авто-разрешён; путь - в системном промпте).
  В shell-редиректах используй **литеральный** путь scratchpad, НИКОГДА не переменную
  (`> $RD/x` песочница считает неанализируемым и спрашивает права).
- В run-директорию файл попадает **только** через `scripts/run_dir.sh stage <dir> <step>
  <файл>…` - скрипт копирует готовый артефакт из scratchpad и делает checkpoint одним
  вызовом. Скрипт единственный в allow-list, поэтому прав не спрашивает.
- Метаданные (`ticket`/`base`/`mode`/…) в `state.json` проставляй
  `scripts/run_dir.sh meta <dir> <k> <v> …` - не через `python`/ручной jq.
- **Никогда** не открывай `Write`/`cat >`/`cd`+`python3` прямо в run-дир - это и есть
  источник постоянных запросов прав.

## 2. Артефакты по шагам

Живут в run-дир (перенесены туда `stage`), рабочие копии остаются в scratchpad:

- `context.md` - шаг 0: host/repo, id MR/PR, полный текст тикета, пути к найденным
  `CLAUDE.md`, список подгруженных `knowledge/**`-файлов ревью-базы, выжимка из доменной базы
  проекта с адресами в ней (для qmd - `qmd://`-пути), краткое summary диффа.
- `draft-review.md` - шаг 1: черновик находок (см. review-engine.md), на выходе шага уже прошедший
  судью (`judge.md`) - с исправленным текстом/severity и секцией «Отклонено судьёй».
- `judge-notes.md` - шаг 1: построчный вердикт судьи по каждой находке (CONFIRMED/CORRECTED/
  SEVERITY-CHANGED/REJECTED + доказательство) - сырьё для шага 4, см. `judge.md` §7 и
  `self-learning.md`.
- `posted.md` - шаг 2: что реально запостили, с возвращёнными URL/id комментариев.
- `human-comments.md` - шаг 4: подтянутые комментарии автора/ревьюеров.
- `state.json` - курсор прогресса.

## 3. Форма `state.json`

Поля: `host`, `repo`, `mr`, `ticket`, `step_completed` (0..4), `base`, `mode`,
`created_at`, `updated_at`. Пути к артефактам НЕ храним - они лежат в `dir` под
фиксированными именами (`context.md` / `draft-review.md` / `posted.md` /
`human-comments.md`). `create` засевает файл, `meta`/`stage`/`checkpoint` дополняют.

```json
{
  "host": "gitlab.example.com",
  "repo": "group/project",
  "mr": "5375",
  "ticket": "PROJ-123",
  "base": "master",
  "mode": "full",
  "step_completed": 1,
  "created_at": "20260724T192300",
  "updated_at": "20260724T193015"
}
```

## 4. Резюмирование

На старте (шаг 0) просканируй `$REVIEW_RUNS_DIR` на предмет директории,
совпадающей по `host` + `repo` + `mr`, у которой `state.json.step_completed < 4`.
(`scripts/run_dir.sh resolve <host> <repo> <mr>` найдёт её за тебя.) Если нашёл -
предложи пользователю **возобновить** со следующего шага вместо перезапуска с нуля.
Восстанови контекст, прочитав существующие артефакты (`context.md`,
`draft-review.md`, `judge-notes.md`, `posted.md`, `human-comments.md`), - не пересобирай то, что уже
собрано.

## 5. Очистка

Удаляй run-директорию **только после шага 4** (self-learning), когда накопленные
знания уже перенесены в базу `knowledge/**`. Никогда раньше: пока шаг 4 не
отработал, директория - единственный способ возобновить ревью из другой сессии
даже спустя дни.

## 6. Дисциплина записи

Пиши на диск **после каждого шага** - но по правилам §1a: артефакт готовишь в
scratchpad, затем одним вызовом `scripts/run_dir.sh stage <dir> <step> <файл>…`
переносишь его в run-дир И проставляешь `step_completed`+`updated_at`. Тогда любой
обрыв сессии оставляет консистентный чекпоинт для резюмирования.

`stage` совмещает перенос финала и чекпоинт. Отдельный `checkpoint <dir> <step>`
нужен, только если шаг не породил нового файла (двигаешь курсор без артефакта). Всё -
через скрипт, вручную `state.json` не трогаем.
