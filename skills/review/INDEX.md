# INDEX - карта накопленного опыта ревью

Читается на шаге 0. Определи `host`/`repo`, затронутую **подчасть** репо (провайдер/сервис/пакет) и
модули из диффа, сопоставь с триггер-словами ниже и подгрузи **только совпавшие** файлы из
`knowledge/**`.

Матчить триггеры механически: `grep -ril '<слово>' knowledge/` - а не на глаз.

**Скоуп этого индекса - только ревью-база:** тон, стилистика, конвенции репо, минорные придирки, мета
«на что смотреть». Фактов «как система работает» здесь нет - они в доменной базе проекта, карта входов
в неё - `knowledge-sources.md`. На шаге 0 грузятся обе.

## Структура ревью-базы

```
knowledge/
  _tone.md                        # общий голос пользователя для всех репо (ВСЕГДА грузить)
  <host>/<repo>/
    _repo.md                      # common-sense по репо + как в нём организованы знания (ВСЕГДА грузить, если есть)
    _tone.md                      # (опц.) поправки к общему тону для этого репо (грузить вместе с общим)
    <подчасть>/<module>.md        # специфика части репо (грузить только затронутые части)
    INDEX.md                      # (опц.) вложенный индекс поддерева, если оно разрослось
```

Структура поддерева `<host>/<repo>/` **своя у каждого репо** и отражает его декомпозицию (провайдеры
или плагины у монорепо, домены/пакеты/слои у микросервиса).

- **Всегда** грузи общий `knowledge/_tone.md`, а также `_repo.md` и `_tone.md` своего репо, если они
  есть. Раскладку и правила self-learning репо смотри в его `_repo.md`.
- Репо-`_tone.md` - **поправки** к общему, не замена: при конфликте побеждает он, остальное берётся
  из общего.
- Из частей грузи **только** затронутые диффом (по пути или триггер-словам) и только совпавшие модули.
- **Триггеры** - слова, по которым файл подгружается: имена каталогов и файлов из диффа, ключевые
  функции/типы/константы, жаргон команды для этой области. Одно слово - один файл; если слово уже
  замаплено, уточняй существующую строку, а не плоди новую (иначе двойная подгрузка).
- **Promotion:** знание, общее для нескольких частей репо, живёт в `_repo.md`, а не дублируется по
  частям; правило тона, подтвердившееся в нескольких репо, поднимается в общий `knowledge/_tone.md`
  (поддерживает шаг 4, self-learning).
- Если поддерево разрослось - у него может быть свой `INDEX.md`; root-INDEX ссылается на него.
