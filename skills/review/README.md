# review

Самообучающийся оркестратор код-ревью MR/PR для Claude Code. Работает с GitLab (`glab`) и
GitHub (`gh`).

Само ревью делает `mattpocock-skills:code-review` в отдельной подсессии. Этот скилл добавляет
вокруг него:

- контекст задачи (тикет из трекера), конвенции репо (`CLAUDE.md`) и выжимку из доменной базы
  знаний проекта;
- прогон `modernize` и паттерны упрощения для Go;
- независимого **судью**, который перепроверяет каждую находку по коду, CI и тикету до того, как
  её увидит человек;
- постинг одобренных комментов inline под именем пользователя и в его тоне;
- **самообучение** на шаге 4: по правкам человека и вердиктам судьи скилл пополняет ревью-базу
  (`knowledge/**`) и доменную базу проекта;
- run-state: прогон переживает перезапуск сессии и возобновляется с последнего шага.

Два режима: **Полный** (черновик → человек отмечает `[x]` → постинг → ручное ревью →
самообучение) и **Короткий** (скилл сам постит high-signal находки после судьи, затем учится).
Подробности - [SKILL.md](SKILL.md).

## Зависимости

Обязательные:

- плагин со скиллом `mattpocock-skills:code-review`;
- `glab` (GitLab) и/или `gh` (GitHub), авторизованные под пользователем, от чьего имени постим;
- `git`, `jq`, `bash`.

Опциональные:

- `qmd` - если доменная база проекта хранится как qmd-коллекция;
- `modernize` (`go install golang.org/x/tools/go/analysis/passes/modernize/cmd/modernize@latest`) -
  механическая проверка упрощений в Go-репо;
- `td` (todoist-rs) - задача-напоминание, если уведомления до пользователя не доходят.

## Установка

```bash
cp -r skills/review ~/.claude/skills/
# или симлинком, чтобы обновлять через git pull:
ln -s "$(pwd)/skills/review" ~/.claude/skills/review
```

Скрипты должны остаться исполняемыми (`chmod +x ~/.claude/skills/review/scripts/*.sh`).

### Права (`~/.claude/settings.json`)

Ревью обычно идёт в worktree другого репо, поэтому правила кладутся в **глобальный**
`~/.claude/settings.json`. Скрипты вызываются строго одной формой - абсолютным путём, без `bash`:

```json
{
  "permissions": {
    "allow": [
      "Bash(~/.claude/skills/review/scripts/run_dir.sh:*)",
      "Bash(~/.claude/skills/review/scripts/glab_post_inline.sh:*)",
      "Bash(~/.claude/skills/review/scripts/fetch_author_comments.sh:*)",
      "Bash(qmd search:*)",
      "Bash(qmd query:*)",
      "Bash(qmd get:*)",
      "Bash(qmd multi-get:*)",
      "Bash(qmd update:*)",
      "Bash(qmd embed:*)",
      "Bash(modernize:*)",
      "Bash(td:*)"
    ],
    "additionalDirectories": ["~/go"]
  }
}
```

`~/go` нужен для чтения исходников зависимостей в GOMODCACHE. Если исходники доменной базы лежат
вне worktree, добавь их каталог в `additionalDirectories`, иначе запись в базу на шаге 4 спросит
права. Строки `qmd`, `modernize`, `td` - только если пользуешься этими инструментами.

### Переменные окружения

- `REVIEW_RUNS_DIR` - где хранить run-директории прогонов (по умолчанию `~/.claude/review-runs`).
- `GITLAB_HOST` - хост self-hosted GitLab, если cwd не указывает на нужный git-remote.
- `REVIEW_USER` - логин, чьи комментарии собирать на шаге 4 (по умолчанию текущий пользователь
  `glab`/`gh`).
- `GITLAB_PROJECT_ENC` - URL-энкодед path проекта, если его нельзя вывести из `origin`.

## База знаний

Стартует пустой и наполняется самообучением:

- [`knowledge/_tone.md`](knowledge/_tone.md) - общий голос комментов (стиль, запреты, формы
  вопросов, длина, исключения). Это единственный предзаполненный файл - **отредактируй его под
  свой голос**, иначе комменты будут звучать как чужие;
- `knowledge/<host>/<repo>/` - появляется после первых прогонов по репо: `_repo.md` (конвенции и
  мета «на что смотреть»), опциональный `_tone.md` с поправками к общему тону, файлы по модулям;
- [`INDEX.md`](INDEX.md) - карта триггеров для ленивой подгрузки;
- [`task-sources.md`](task-sources.md) и [`knowledge-sources.md`](knowledge-sources.md) - откуда
  брать тикеты и доменную базу для каждого репо; при первом контакте с репо скилл спросит и допишет
  запись сам.
